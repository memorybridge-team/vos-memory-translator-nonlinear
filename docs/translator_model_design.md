# Translator model design

This note describes the two translator models after the refactor on `feat/translator-model-refactor`, and gives the source of every part. It continues `docs/translator_design_literature_grounding.md` (the literature report), which stays valid for the background. Where the two differ, this note describes the code.

Code: `src/vos_memory_inspector/models/_stitched.py` (all parts), `residual_mlp.py` and `transformer.py` (the two models).

Match strength uses four levels: direct precedent, close analogy, loose analogy, none. "Follows from the model" marks a part that SAM 2's own construction requires.

## 1. Structure

Both models translate one memory record at a time. No information crosses records, objects or frames. A record has a spatial memory `M` of shape [64, 64, 64] (channels, height, width) and an object pointer `p` of length 256.

Spatial memory, read as 4,096 tokens of 64 channels:

```
Z     = S(M) = W M + b            linear stitching layer, the same at every position; W, b start from ridge regression
Z     = Z + Attn(LN(Z))           Transformer model only
M_hat = Z + FFN(LN(Z))            both models
```

Object pointer:

```
p_hat = A p + c                   linear; A, c start from ridge regression
```

- **MLP model** (`residual_mlp`, class `ResidualMLPStateTranslator`): stitching layer, then one Pre-LN block that has only the feed-forward sublayer.
- **Transformer model** (`transformer`, class `TransformerStateTranslator`): the same, with a self-attention sublayer before the feed-forward sublayer. That makes the block a standard Pre-LN Transformer encoder block.

The last linear layer of each sublayer starts at zero. So an untrained model equals its stitching layer: the closed-form linear baseline after `initialize_from_ridge`, and the identity before it (a placeholder only).

Not translated: frame indices, slot order, validity, object ids. Position encodings of the memory are regenerated by the target model.

In one sentence for the paper: *the translator is a linear stitching layer followed by one Transformer encoder block; the MLP variant removes the attention sublayer from that block.*

## 3. Components shared by the two models

| Component | MLP model | Transformer model |
|---|---|---|
| Stitching layer `S` (64 -> 64, ridge start) | yes | yes, identical |
| LayerNorm + feed-forward sublayer (64 -> 256 -> 64, zero start) | yes | yes, identical |
| LayerNorm + spatial-reduction self-attention (with its sine position encoding) | **no** | **yes** |
| Linear pointer head (256 -> 256, ridge start) | yes | yes, identical |
| Record handling, dtype policy, payload format, ridge initialisation | yes | yes, same code (`StitchedStateTranslator`) |

The two models differ in exactly one component. The Transformer model contains the MLP model: with the attention output projection at zero, the two compute the same function (tested in `tests/test_stitched_models.py`). A comparison between them is therefore an ablation of the attention sublayer.

They do not have the same size. If a reviewer asks whether attention or the extra parameters cause a difference, the preset `residual_mlp_matched` (feed-forward ratio 14, hidden width 896) has 119,936 spatial parameters against 119,872 for the Transformer model. It is one configuration value (`configs/state_training/residual_mlp_matched.json` for the trainer), so it was cheap to add. It is a control, not a third model.

Why the numbers moved:

- Parameters went down for both models (349,440 -> 103,168 and 457,216 -> 185,664), mostly because the pointer MLP (262,912 or 328,704) became a linear map (65,792).
- The feed-forward ratio went from 2 to 4, the ratio of Vaswani et al. and ViT. This doubles the feed-forward cost (67 M -> 134 M MACs).
- The Transformer model now computes attention for all 4,096 positions instead of for 256 coarse tokens. This removes the convolution and upsampling that had no reference, and costs more MACs (78 M -> 338 M per record).

### Smoke test on real states (not a training run)

To check that the same code trains for every pair, both models were run for 300 updates on stored states: 60 MOSEv2 train cases from different videos (48 to fit, 12 held out), ridge start fitted on the 48, batch of 8 records, AdamW at 3e-4, gpu-server GPU 0, under two seconds per run, nothing saved. Held-out error is the MSE divided by the target variance.

| Pair | Model | Spatial: identity | Spatial: ridge start | Spatial: after 300 updates | Pointer: ridge start | Pointer: after |
|---|---|---:|---:|---:|---:|---:|
| Small -> Base+ | `residual_mlp` | 2.540 | 0.1623 | 0.1560 | 0.2944 | 0.2969 |
| Small -> Base+ | `transformer` | 2.540 | 0.1623 | 0.1546 | 0.2944 | 0.2969 |
| Base+ -> Large | `residual_mlp` | 1.250 | 0.2321 | 0.2176 | 0.4187 | 0.4175 |
| Base+ -> Large | `transformer` | 1.250 | 0.2321 | 0.2134 | 0.4187 | 0.4175 |
| Small -> Large | `residual_mlp` | 1.519 | 0.2439 | 0.2325 | 0.3897 | 0.4021 |
| Small -> Large | `transformer` | 1.519 | 0.2439 | 0.2310 | 0.3897 | 0.4021 |

What this shows: the code runs for the three pairs with real Small, Base+ and Large states, the loss is finite, and the held-out spatial error falls below the ridge start in every case. The identity gives an error above 1, that is, worse than predicting the mean, which is why the identity is only a placeholder. What it does not show: anything about tracking accuracy, or about which model is better. 60 cases and 300 updates are far too few, state error does not predict J&F in your records, and the pointer numbers rest on a ridge fit with only 701 pointers.

## 5. One structure for three pairs

- Nothing in the model depends on a pair. The classes take a source and a target `StateSpec`; all three pairs use `SAM21_MEMORY_SPEC` (64, 64, 64, 256).
- The shapes were checked on stored states of all three sizes on gpu-server (same case, Small, Base+ and Large): spatial `[1,1,16,64,64,64]` bfloat16, pointer `[1,1,16,256]` float32.
- The scales differ per model (spatial RMS about 1.03, 0.76, 1.39; pointer RMS about 0.25, 0.58, 0.62 on that case). The model has no constant tied to a scale: the stitching layer absorbs it, and LayerNorm makes the sublayers see normalised input for every pair. Loss normalisation by the target scale is done in the training loop from train-split statistics, per pair.
- What may differ per pair: the weights, the ridge solution, the learning rate, the number of updates and the loss weights. They belong to the training configuration.
- Tests build both models for the three pairs and run synthetic states with the scale of each size (`tests/test_stitched_models.py`).

**Claims the sources do not support, so do not make them**

- That a per-position linear map is sufficient for memory translation. The stitching papers show it for classification networks.
- That spatial context is needed. Lin et al. give a reason to expect a mismatch between architectures; nobody has shown it for SAM 2 memory.
- That the least-squares start is good enough on its own. Csiszárik et al. and Pan et al. both report that it is not, without further training.
- That one structure works equally well for all three pairs. Pan et al. report that stitching non-neighbouring sizes is worse, and Small -> Large is such a pair.
- That the block adds only a *small* correction. In the short diagnostic of `docs/paper_check_report.md` the correction was 12 to 23% of the stitched memory when the linear maps stayed at the ridge solution, and 34 to 46% when they were trained together with the block. Write "a correction", not "a small correction".
- That the output keeps the scale of the target memory. In the same diagnostic the output had 85 to 90% of the target's per-channel standard deviation (82 to 88% for the ridge map alone). No cited source deals with this; Maiorca et al. 2023 standardise both spaces and de-normalise into the target's statistics.
- That attention helps. Bansal et al. 2021 found that a larger stitching kernel changes little for two networks of the same architecture, and in the diagnostic attention beat its size-matched control on two pairs and lost on one, in state error only.
- An accuracy claim beyond section 7. Only the Small -> Base+ Transformer has been trained and evaluated, with one seed. The MLP model and the pairs Base+ -> Large and Small -> Large have not been trained with this structure.

## 7. Fine-tuning through the frozen target

The structure alone does not explain the accuracy. Training it on the state error (the official trainer, `cmmt-state-training`) gives a model that ties the paper's Translator. A second stage then trains the translator through the frozen Base+ model, and that stage gives most of the gain (table below). This section gives the sources of that stage. The sources were read in the PDFs on 2026-11-15, and pages are those of the PDF on disk.

**What the stage does.** One training item is a stored case and one frame after its switch. Base+'s own memory attention and mask decoder read that frame twice: once with the true Base+ records (the teacher) and once with the records replaced by translated ones (the student). Base+ stays frozen, and only the translator's spatial path is trained; the linear pointer map stays frozen. The loss pulls the student toward the teacher:

```
loss = 10 * feature + 5 * mask + 0.5 * score + 0.1 * state
feature = ||F_s - F_t||^2 / var(F_t)              memory-conditioned feature, the input of the mask decoder
mask    = BCE(mask logits_s, sigmoid(mask logits_t))   soft teacher mask, on the mask the teacher picks
score   = BCE(object score logit_s, [logit_t > 0])
state   = ||M_hat - M||^2 / sigma^2                the official trainer's state error, kept as a small term
```

Each item is used in one of two scenarios: `cond` (70%) translates the conditioning record and keeps the true recent records; `all` (30%) also translates the recent records read at switch + 1. Settings used: 12,000 updates, batch 4, AdamW at learning rate 1e-4 with a 200-step warm-up and cosine decay, gradient clipping at 1, seed 7. The run starts from the translator selected by the official trainer. Two variants were trained. `ft` attaches the translator's own pointer to translated records, as at run time. `ftt` attaches Base+'s true pointer, as the earlier design-review recipe did.

- `ftt` minus `ft`: at most +1.94, and every CI contains 0. The pointer variant used in training does not matter measurably.
- PUMaVOS has 26 cases on 24 videos, and M3-VOS has 110 cases on 81 videos. Neither set was used for training or model selection. The paper row is a mean over the same PUMaVOS cases from the paper's own database; it is not a paired difference.
- The fine-tuning's own held-out split overlaps the official trainer's training data, so its held-out numbers were not used to choose anything. The run keeps the last weights.

**Why fine-tuning reaches Base+ alone and no further.** The teacher is Base+ with its own records, so a perfect student reproduces Base+ alone. On these two sets Small alone is better than Base+ alone, so this target cannot carry Small's better track across the switch. The fine-tuned model is already within the noise of that ceiling.

Sentence for the paper: "After training on the state error, we fine-tune the translator through the frozen target model: the target's memory attention and mask decoder read a frame after the switch with true and with translated records, and the translator is trained so that the second read matches the first, as in task-loss matching of stitched networks (Csiszárik et al., 2021). This raises J&F by 3 to 4 points on PUMaVOS and by 1.7 points on M3-VOS, to the level of the target model running alone."

Do not claim that fine-tuning beats Base+ alone or Small alone, that it holds for other pairs, or that one pointer variant is better.
